## 새로 배운 내용
### 동시성

- 하나의 CPU에서 여러 작업이 동시에 실행되는 것처럼 보이는 것 -> 실제로는 작업을 빠르게 전환하는 방식

#### 스케줄러
- 운영체제의 핵심 구성 요소로, CPU와 같은 시스템 자원을 적절히 분배하기 위해 프로세스나 스레드의 실행 순서를 관리함

1. 자원 독점: 무거운 연산이 들어오면 계속 이것만 처리하게 된다.
2. 기아 생태: 가장 빠르게 처리할 수 있는 프로세스부터 처리한다고 하면 무거운 연산은 계속 우선순위가 밀려서 처리되지 못함.
3. 시스템 낭비: 디스크의 I/O를 기다리면 CPU자원이 낭비됨.

##### 스케줄러의 목표
- CPU 이용률 최대화 (단위시간당 처리할 수 있는 작업의 양 최대화)
- 결국 CPU를 최대한 빈시간 없이 활용하고 싶다.
- 공정성 확보

##### 기능
1. 작업 선택: 다음에는 어떤 프로세스를 작업할지 정함.
2. 자원 분배: 선택한 작업 CPU 권한 분배
3. 컨텍스트 스위칭 관리: 기존 작업 상태 PCB에 저장 

##### 스케줄러의 종류
1. 장기 스케줄러
    - 보조기억장치에 있는 프로그램 중 어떤걸 RAM에 올려야 하는지
2. 중기 스케줄러 (스왑 관리자) 
    - 메모리를 사용하다 부족하면 프로세스 중 일부를 중단시켜서 디스크로 옮기고 여유가 생기면 다시 가져옴.
    - 가상메모리
3. 단기 스케줄러 (CPU 스케줄러)
    - 메모리의 준비 상태로 있는 프로세스 중에서 CPU에 할당 받을 프로세스를 결정함.

##### 순서
1. 작업 대기열 관리
2. 우선순위 설정
3. 자원 분배
4. 작업 전환
5. 완료 및 자원 해제

#### 스케줄링
- CPU와 같은 자원을 프로세스와 스레드들이 사용할 수 있도록 줄을 세우는 것

##### 스케줄링의 레벨
1. 고수준 스케줄링
    - 메모리에 올릴 프로세스 결정
    - 시스템의 전체 부하를 조절하는게 목표

2. 중간 스케줄링
    - 메모리 부족할 때 일부 프로세스를 잠시 내보내는 역할.
    - 스왑이랑 비슷한 느낌.
    - 메모리를 확보하는 것과 시스템의 안정성을 유지하는 것이 목표

3. 저수준 스케줄링
    - CPU를 누구한테 할당할지
    - 보통 스케줄링을 말하면 이것임.
    - Job Queue (고수준 스캐줄링)
    - Ready Queue (저수준 스캐줄링)

##### 스케줄링 알고리즘

1. FCFS(First Come First Served)
- 먼저 온 작업 처리
- 간단한 알고리즘
- 앞의 프로세스가 오래걸리는 것이면 계속 기다려야함. -> Convoy Effect

2. SJF(Shortest Job First)
- 가장 짧은 작업 먼저 처리
- 평균 대기시간이 제일 적다.
- 운영체제에서 가장 효율적이다.
- 하지만 너무 이상적이다. 실제로는 프로세스가 실행될 시간을 예측하기 어렵다.
- 오래걸리는 작업이 계속 기다리는 기아 현상이 나올 수 있음.

3. SRTF(Shortest Remaining Time First)
- 남은 시간이 가장 짧은 프로세스를 실행
- SJF 선점형 버전 (선점형: CPU가 프로세스를 실행하고 있는데 중간에 다른 프로세스로 갈아 탈 수 있음.)
- 응답성이 좋아짐
- 컨텍스트 스위칭 비용이 높아짐.

4. Priority 
- 우선 순위가 높은 프로세스 실행
- 시간에 상관없이 중요한 작업을 먼저 할 수 있음.
- 기아 상태가 발생할 수 있음.

5. RR(Round Robin)
- 모든 프로세스에게 동일한 CPU 시간 제공
- Time Slice
- 공정하고 응답성이 준수함.
- 타임 슬라이스가 너무 작으면 컨텍스트 스위칭 비용이 높고 너무 크면 응답성이 안좋음.
- 때문에 Time Slice를 설정하는 것이 어려움.

선점형 
- 운영체제가 CPU의 자원을 강제 회수
- Linux,Window,Mac
- 작업을 동시에 실행해야하기 때문에 요즘 운영체제는 선점형이다.

비선점형
- 강제 회수가 안됨.
- FCFS,SJF

#### Multilevel Queue

- 프로세스를 그룹별 나눠서 관리
- 각 그룹 큐마다 다른 알고리즘 사용

실시간 작업 -> 우선순위
일반사용자 -> 작업 라운드로빈
배치 작업 -> FCFS 

#### 병렬성
- 여러 CPU 코어 또는 여러 프로세서를 사용하여 여러 작업을 물리적으로 동시에 실행

##### 병렬성과 동시성의 차이
- 병렬성은 진짜로 병렬처리
- 동시성은 병렬로 처리하는 것처럼 보이는 순차처리

##### 병렬 동작 방식
1. 작업 분할: 큰 작업을 여러개로 나눔
2. 코어 할당: 분할된 작업 CPU 코어에 할당함.
3. 병렬 실행: 각 코어에서 실행함.
4. 결과 통합
5. 오류 처리

1. 병럴성이 항상 좋은 것은 아님
- 작업을 분할, 결과 합치는 비용이 생각보다 비싸다.
- 작업 분할 비용 + 스레드 생성 비용 + 결과 병합비용

2. 공유 자원 주의
- 여러개의 코어가 병렬처리 하기에 동시에 접근하는 자원이 발생함.
