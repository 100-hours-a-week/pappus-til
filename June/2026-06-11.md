### 세마포어
- 공유 자원에 접근 할 수 있는 허가권의 개수를 관리해서, 동시 접근 가능한 스레드 수를 제한하는 동기화 도구 (이거 완전 락 아니야? -> 락은 하나씩, 세마포어는 어느정도 한정된 수만큼)


#### 사용이유
- 공유자원에 너무 많은 접근이 이루어지면 장애나, 성는 저하가 발생함.

1. 자원 보호: 한정된 자원을 동시에 너무 많이 사용하지 않도록 제한
2. 동시성 제어: 여러 스레드가 동시에 실행되더라도 안전하게 순서 조정
3. 시스템 안정성: 과도한 요청으로 시스템이 꺼지지 않게 보호

#### 사용처
- DB 커넥션

#### 세마포어 개념
1. 세마포어 값 S
S: 현재 사용 가능한 허가권의 개수

2. P연산
P: 허가권을 하나 가져가는 연산

3. V연산
V: 허가권을 하나 반납하는 연산

#### 세마포어 종류
1. 이진 세마포어
- 값이 0,1뿐임.
- 단일 자원 접근 제어 (? 이건 진짜 락인데? -> 뮤텍스는 오너가 잠궜다. 세마포어는 몇 개의 허가권이 남았냐라는 설명)

2. 카운팅 세마포어
- 값이 0이상의 정수로 동작 , 여러개의 자원 접근 제어

#### 세마포어와 락의 차이
- 세마포어는 락이 아님.
- 세마포어는 잠금이 아니라 허가권 관리에 가깝다.
- 뮤텍스는 한명이 가져가면 가져간 사람이 반납해야 사용할 수 있음
- 세마포어는 한명이 가져가고 나가면 입장권을 관리하는 것이 생성함.

#### 적용
1. 외부 API 호출 제한
- 짧은 시간에 많은 api 요청을 보내는 것은 공격으로 간주됨
- 공격으로 간주되지 않는다고 해도, 우리 스레드가 외부 API에 많이 할당되어서 서비스 퀄리티가 외부 API에 의해 좌지우지된다.
- 그래서 요청을 한번에 와락 보내지 않도록 하기 위해서 세마포어를 사용

2. 파일, 이미지 처리 서버
- 스레드 풀 개념
- 파일이나 이미지 처리하려면 메모리 자원이 상당히 많이 듦.

3. 배치 작업
- 한 번 처리에 자원이 많이 필요한 경우가 빈번함.

4. 로드 벨런서
- WS -> WAS 들로 부하 분배
5. Nginx Web Server 동시 연결 제한
6. Rate limit
