### Portainer
- Docker와 Kubernetes 같은 컨테이너 환경을 손쉽게 관리할 수 있도록 해주는 웹 기반 GUI 관리 도구
- 도커 엔진 + API, Portainer Agent
- ** 포테이너 컨테이너를 절대로 외부 인터넷에 노출하면 안됨. ** 

#### 필요한 이유
```
docker ps
docker logs
docker restart
docker exec -it
docker network ls
docker images
docker volume
```
- 도커를 사용할 때는 CLI 환경에서 명령어로 동작함.

1. 상태 파악이 어려움.
2. 명령어 실수
3. 운영 접근성이 낮음.
- CLI 환경은 GUI보다는 접근성이 떨어짐.
4. 여러 서버 관리가 불편함.
5. 설정이 눈에 보이지 않음.
- 이것도 운영 접근성과 같은 이유
- 개인적인 생각: 이것들은 단점이라고 하기에는 애매하다고 생각함. 배우면 된다고 생각함. 일반인이 쓰기 어려워서 GUI로 바꾸는 것은 이해되지만 이것은 애매한 것 같다. 

#### Docker Desktop vs Portainer
- 도커 데스크탑은 로컬 환경에서 관리함.
- portainer는 서버 환경에서 관리함.
- 옵저빌리티를 위해서 Portainer를 사용함.

#### 실무에서 사용

1. 운영 가시성 확보
- 실무에서 장애가 발생했을 때 보통 필요한게 어떤 컴포넌트, 컨테이너가 죽어있냐임.
- 컨테이너의 상태, 컨테이너가 이미지 버전을 몇 사용했냐, CPU, RAM 자원 사용량

2. 개발자 - DevOps 협업
- 포테이너는 도커를 보기 쉽게 하기 위해서임.
- 개발자는 코드를 만들어서 CICD 파이프라인 돌리고 정상 테스트 통과하는 것이 중요함.
- DevOps는 실제 배포가 안정적으로 되냐가 중요함.

3. 쇼규모 운영
- 대형 중앙 집중 로그, 메트릭 수집 툴은 무겁고 설치하고 관리하기가 까다로움.
- 소규모는 간단하게 포테이너 설정에서 관리하는 것이 효율적임.

** 주의사항 **
1. GUI 바꾸면, 실제로 변경됨.
2. RBAC 접근 제어를 해야함.
- 사용자 권한 관리
- 실수를 한 사람과 실수를 할 수 있도록 환경을 만든 사람 둘 다 책임을 지게됨. 
3. Portainer 보안 사항 준수해야함.
- Private subnet에 넣어서 사용하고 VPN or Bastion Hoat를 활용해서 다루어야함.
- Admin 계정에 대한 공유

### Volume 
- 컨테이너 간 데이터 공유 및 영속성을 제공하기 위해 호스트 파일 시스템에 생성되는 독립적인 저장소

- 컨테이너 안에 파일을 저장하면 영속성이 필요한 컨테이너를 만들면 컨테이너 내부 경로에 저장됨.

```
docker rm mysql-test
// 컨테이너 내부에 있는 저장 공간도 같이 삭제됨
```
- 컨테이너는 이미지 위에 쓰기 가능한 임시 레이어를 얹어서 동작하기에 비영속적임.
- 변경사항은 이미지에 저장되는 것이 아니라 읽기 쓰기 레이어에 저장됨. (쓰기 레이어가 컨테이너 생명 주기를 공유함.)
    - 컨테이너의 목적은 빠르게 생성 및 제거임.
    - 또한 배포 단순화를 위해서 컨테이너에서 영속성 저장이 없어야 편함.

- 컨테이너 내부에 데이터를 쓰지 않고, 외부에 데이터를 작성함 (Host OS)

#### 사용 이유
1. 데이터 영속성
2. 데이터 공유 

#### 실무에서 사용

1. 데이터베이스 컨테이너
- 그런데 나는 굳이 사용할까 싶음. 

2. 파일 업로드 템프 폴더
- EC2 내부에 WAS container 3개 돌아간다면 공유가 필요하기에 사용할만함.

3. 설정 파일 마운트
- Nginx 설정
- Spring env 파일

4. 로그 보관
- 컨테이너 로그는 보통 컨테이너 내부에 생성됨
- 그런데 컨테이너가 삭제되는건 오류가 발생할 때. 이를 해결하기 위해서 volume을 사용함.
