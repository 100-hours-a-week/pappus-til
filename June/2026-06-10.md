## 새로 배운 내용

### 공유 자원
- 여러 사용자나 프로세스, 스레드가 동시에 접근하거나 사용하는 시스템 내의 자원
- 메모리, 파일, 데이터베이스, 네트워크 소켓, 전역 변수

#### 사용 효과
1. 메모리 절약
2. 데이터 일관성 유지
3. 프로세스 간 협업
4. 동시에 공유자원에 접근하기에 무결성이 깨짐.

### 임계 영역
- 공유 자원에 접근하는 코드

- 데이터 무결서 유지
- 경합 조건 방지
- 예측 가능한 프로그램 실행
- 시스템 안정성 확보

#### 문제점
1. 경합 조건: 여러 스레드가 동시에 공유 자원에 접근할 때 실행 순서에 따라 결과가 달라지는 문제. 

2. 데이터 무결성: 데이터가 논리적으로 맞지 않은 상태

4. Deadlock
- 여러 스레드가 서로 자원에 접근하려고 영원히 기다리는 상태

#### 해결법 - 동기화

- 동시에 들어가지 못하게 한다.
- 작업이 끝나면 반드시 나오게 한다.
- 무한정 기다리지 않게 한다.
- 필요한 구간만 보호한다.


### 동기화
- 여러 스레드가 데이터를 안전하게 읽고 쓸 수 있게하는 기술

#### 임계 영역에 문제를 해결하는 3가지 조건
1. 상호 배제 (Mutual Exclusion): 임계영역에는 하나의 프로세스만
2. 진행 (Progress): 임계영역이 있고 들어가려는 프로세스가 있으면 누군가는 들어가야함
3. 유한 대기 (Bounded Waiting): 프로세스는 무한히 기다리지 않음.

#### 동기화 하는법
1. Lock/Mutex 사용
- 한번에 하나의 스레드만 임계영역에 들어가도록 하는 락 (? 그냥 락이랑 차이 없지 않나? -> 락은 자물쇠고 Mutex는 자물쇠를 어떻게 사용하는지에 대한 기술인것 같음.) 
- 락 사용시 finally 꼭 사용해야함.

2. 세마 포어
- 임계 영역에 들어갈 수 있는 입장권의 개수가 정해져 있음.

3. Atomic 연산
- 읽기, 수정, 저장을 하나의 쪼갤 수 없는 연산처럼 처리하는 방식
- 단순 카운터 증가하는 연산은 아토믹 자료가 좋음

```java
AtomicInteger counter = new AtomicInteger(0);
counter.increamentAndGet();

```

4. 트랜잭션
5. 임계 영역을 최대한 축소

##### CAS 연산
- stock.get(), decrementAndGet()을 따로 쓰는 것이 아니라, 내가 읽은 값이 아직 그대로일 때만 차감한다를 보장함.

#### 락 
- 공유자원 앞에 걸어두는 자물쇠

1. 스핀 락
- 락이 풀릴 때까지 계속 확인하는 락.
- 락을 얻지 못할 때, 스레드가 잠들지 않고 계속 확인함.
- Busy-waiting

2. 낙관적 락
- 충돌이 거의 없다고 가정을 함.
- 작업을 먼저하고 검사해서 이상하면 롤백이나 재시도
- 읽기가 많고 쓰기가 적은 시스템

3. 뮤텍스
- 뮤텍스는 한 번에 하나의 스레드만 자원에 접근하게 하는 대표적인 락임.(대기큐 사용)
- 락을 획득한 스레드만 락을 해제할 수 있다.
- 병렬성 감소, 컨텍스트 스위칭 오버헤드, 데드락 위험.

4. read write lock
- 읽기는 여러명, 쓰기는 한명만
- Reader, writer사용
- 읽기 요청이 많은 요청에 사용
- 구현이 뮤텍스보다 복잡함. 
- 오버헤드 존재, 쓰기가 많으면 성능이 떨어짐.
- reader가 모두 읽을 때까지 Writer은 starve 상태 (writer가 들어오면 reader보다 우선하는 것으로 해결하기도 함.)
- 동시성이 높음, 뮤텍스보다 효율적일 수 있음.
