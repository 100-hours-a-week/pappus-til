### 메모리 주소체계

메모리 주소 동작 방식
- 운영체제가 관리하는데 운영체제는 하드웨어 RAM에 애플리케이션이 접근 못하게 차단
- 하지만 애플리케이션은 메모리에 접근해야함.


1. 논리주소 (Logical Address)
- 프로그램이 바라보는 메모리 주소
- 실제 메모리 주소가 아님. 그래서 자바에서 객체의 메모리 주소를 찍으면 논리주소가 나옴.
- 프로그램은 메모리를 자기가 0번부터 사용하고 있다고 생각한다.

2. 물리주소
- 실제 메모리 주소

3. MMU(메모리 관리 장치)
- 주소변환을 해줌.

오버레이 기법
- 하나의 메모리 공간에 프로그램 실행을 위해서 개발자가 직접 코드를 모듈로 쪼개고 필요한 조각만 올려서 사용하는 방식
- 현재는 잘 사용하지 않음.

- 개발자가 코드를 모듈로 쪼갬. 운영체제가 프로그램이 실행될 때, 어디부터 어디까지 필요한지 모름.
- 개발자가 코드 짤 때, 메모리에 올라갈 모듈을 분리하고 메모리 공간을 고려해야함. 그래서 개발 난이도가 높음.

메모리 스왑
- 사용하지 않는 데이터를 디스크의 스왑공간으로 이동하여 RAM 메모리를 확보하고 필요할 때 메모리로 복구하는 방식.
- 잘못 스왑하면 속도가 상당히 느려짐
- 스레싱
    - 메모리가 많이 부족하면 스왑을 자주함
    - 스왑하는 것도 프로세스를 점유해서 자주발생하면 스왑처리에 자원이 많이 들어서 컴퓨터가 멈춘것처럼 보임.

오버레이는 단일 프로그램의 크기 제한 극복을 위해서
스왑은 여러 프로그램을 동시에 실행하기 위한 공간 확보하기 위해서 사용함.

### 메모리 관리 단위

1. 고정 분할 방식
- 단순하기에 빠르게 할당 할 수 있다.
- 임베디드 시스템에서 많이 사용함.

2. 가변 분할 방식
- 프로세스 크기에 맞춰서 할당함.
- 메모리 내부 단편화로 인한 메모리 공간의 낭비를 없애기 위해서 만들어짐.
- 메모리를 효율적으로 사용함.
- 외부 단편화 -> 듬성듬성 비어있는 자리를 합치면 충분한 공간이 나오는데 비어있는 자리가 따로따로 있어서 새로운 프로그림을 넣지 못함. -> 공간을 압축하기 위해서 프로그램을 멈춰서 압축하고 공간을 확보함.

패이징 기법
- 메모리와 프로그램 둘다 4KB로 고정된 크기의 조각으로 짤라서 빈 공간에 저장
- 메모리를 비우지 않아도 된다.
- 페이지 테이블을 사용하기 위해서 메모리를 추가로 사용
- 주소 변환에 시간이 걸림.

세그멘테이션 기법
- 프로그램의 논리적인 의미 단위로 잘라서 보관
- 프로그램의 구조를 그대로 반영해서 데이터 보호하기 편함.
- 세그먼트가 크기가 제각각이라 외부 단편화 발생함.

현대 OS방식
- 페이징, 세그멘테이션을 혼합
    - 세그먼트 방식으로 나누고 페이징으로 다시 나눔.

### IPC(Inter-Process Communication)

- 다른 프로세스에 메모리 접근할 필요가 있음. 이때 프로세스 간 통신을 위해 제공하는 것이 IPC

1. 메세지 전달 
    - 운영체제 커널 (메세지를 서로 주고 받는 방식)
    - 직접적인 메모리 공유 없이 안전하게 통신함.
2. 공유 메모리
    - 프로세스끼리 공유할 수 있는 메모리 공간을 만드는 방식
    - 통신이 빠르기는 한데 동시성 접근제어를 해야함.
    - 접근 프로세스가 많은 경우는 동기화 문제가 자주발생하여 효율이 떨어짐.

### PCB (Process Control Block)
- 스케줄링 등 운영체제의 핵심 기능을 이해하고 최적화하는데 필수적.
- CPU가 여러가지의 프로세스를 빠른속도로 번갈아가면서 실행함. -> 병렬적으로 실행하는 것처럼 보임.
- CPU는 무슨 작업을 했는지 기억하지 못하기에 그것을 PCB에서 기억해줌.
- 싱글 스레드에서도 병렬적으로 작업 할 수 있는 것이 이것 때문인가?

1. 프로세스 생성
2. 실행 상태 기록
3. 문맥 교환 관리
4. 자원 정보 관리
5. 프로세스 종료


### 한줄 정리

 1. 운영체제: 컴퓨터를 사용자가 원활하게 사용할 수 있도록하는 소프트웨어.
 2. 유저 모드, 커널 모드: 사용자가 컴퓨터를 다루는데 실수를 하더라도 문제가 없도록 직접적인 하드웨어 관리를 하지 않는 곳과 하는 곳
 3. 메모리 구조: 운영체제가 프로그램을 실행시키기 위해 메모리에 할당하는 구조
 4. 메모리 관리자: 메모리를 효율적으로 관리하기 위해 자동적으로 프로세스의 메모리 할당을 함
 5. 메모리 주소 체계: 데이터를 효율적으로 메모리에서 다루기 위해 만들어진 체계
 6. 메모리 관리 기법: 제한된 메모리 환경에서 프로그램을 돌리기 위한 방법
 7. 메모리 관리 단위: 메모리를 효율적으로 저장하기 위한 단위
 8. 가상 메모리: RAM의 제한을 극복하기 위해서 보조기억장치에 정보를 저장하고 RAM에 매핑하는 방식
 9. 프로세스, 스레드: 프로그램이 실행되는 단위와 프로그램 내에서 어떠한 동작이 실행되는 단위

 - 운영체제:컴퓨터를 사용자가 원활하게 사용할 수 있도록하는 소프트웨어.
 - Kernel: 사용자가 하드웨어를 직접 관라할 수 있는 공간과 아닌 User 공간으로 분리해서 잘못된 하드웨어 관리로 인한 불상사 방지
 - System Call: 
 - Virtual Memory: 스왑 기술과 비슷한 기술이라 생각함. 한정된 RAM의 자원 이상의 작업을 하고 싶을 때 사용
 - Swap: RAM에서 감당 할 수 없는 프로세스를 다루기 위해서 처리하기 위해 하드웨어에서 RAM에 필요없는 데이터 일부를 바꿔치기 하는 방식
 - Paging: 일정한 크기로 잘라서 빈 틈사이로 데이터를 저장하는 방식
 - Segmentation: 논리적 Paging기법
 - Intenal / Extenal Fragmentation: 할당된 공간 안에 남는 공간이 있냐 할당되지 않은 공간에 남는 공간이 있냐
 - Process: 하나의 프로그램이 실행되는 과정
 - Thread: 하나의 프로세스의 하나의 동작이 실행되는 공간
 - IPC: 관련도가 적은 프로세스끼리의 통신을 가능케 하는 것 (Discord의 게임 화면 공유나 게임 안에서 Discord를 동기화 해서 통신할 수 있도록 해주는 것인가?)
 - PCB: CPU가 동시처리를 할 수 있도록 어디까지 했나 저장하는 곳.
