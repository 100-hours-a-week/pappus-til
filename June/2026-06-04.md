### 스프링 예외처리

1. try-catch
- 단순한 프로그램에서는 쓸만하다.(구현이 간단해서 그런듯)
- 하지만 다른곳에서 비슷한 예외처리가 필요한데 그럼 필요한 곳마다 코드를 작성해야함 -> 중복이 많아져서 불편함

2. BasicErrorController
- 에러처리라는 공통관심사 해결
- 안그래도 DispatcherServlet 할일 많은데 예외처리도 담당해야하게 됨.
- 예외 발생 시, 위 컨트롤러 호출하고 WAS에 전달함.
- 별도 설정 없으면 여기서 에러 처리함.
- 예외 처리 응답은 지정되어 있어서 유의미한 에러 전달이 힘듬

3. @ResponseStatus
- 에러 HTTP 상태를 변경하는 어노테이션
- 응답은 BasicErrorController에서 담당

4. ResponseStatusExeption
- 스프링5에서 추가된 예외 응답
- 예외처리 빠르게 적용 가능
- HttpStatus 설정으로 예외 클래스 결합도 낮음
- try-catch와 같이 사용하기에 중복이 발생하는 단점을 공유함.

5. @ExceptionHandler
- 유연하게 에러처리 가능
- 어노테이션 추가로 에러처리가능
- 현업에서 주로 사용한다고함.
- 컨트롤러에서 구현하는 방식
- 예외처리 코드 중복


-> 그래서 전역으로 처리하는 기술이 있음

6. @ControllerAdvice , RestControllerAdvice
- 스프링 전역으로 @ExceptionHandler 적용함.
- 하나의 클래스로 모든 컨트롤러 전역 예외 처리
- Enum이나 CommonErrorCode로 형식을 정함.
- 예도 DispatcherServlet에기 일을 부담시킴. (성능 면에서는 BasicErrorController과 같은 것네)

### Filter , Intercepter
- filter -> controller -> Intercepter

1. Filter
- Servlet Context안에 있지만 Spring Context 밖에 있음.
- DispatcherServlet 앞에 존재함.
- 스프링 프레임워크와 무관하게 작동 가능
- filter에서는 예외처리에 사용하는 Bean을 사용하지 못하기에 try-catch를 사용하는 편, 아니면 에러 구현체를 만들기도 함.

#### 사용처
- 공통 보안, 인증/인가
- 모든 요청에 대한 로깅
- 이미지 데이터 압축 및 문자열 인코딩
- 스프링과 분리되어야 하는 기능

#### doFilter
- DispatcherServlet에 전달 전에 실행
- FilterChain 

필터 체인
- 서블릿 컨테이너가 관리하는 필터들의 연결고리
- 필터 등록 순서대로 처리함.

### Intercepter

- Dispatcher Servlet에서 컨트롤러 요청 전에 거치는 것
- 스프링에서 제공하는 기술
- 요청과 응답 참조 및 가공
- 세부적인 보안, 인증/인가

preHandle
- 컨트롤러 호출 전 실행

postHandle
- 컨트롤러 호출 후 실행

afterCompletion
- 모든 작업이 완료된 후 실행

### 차이

filter : 전역 로직(인코딩 , XSS 필터링 등)
Intercepter: 컨트롤러 관련 공통된 로직(요청별 공통 데이터 주입 등)
AOP: 스프링 빈 메서드 관련 로직(트랜잭션 등)

강사님의 생각 
- 인증/인가는 필터에서 모두 구하는 것이 좋을 것 같다.
- HTTP 요청을 제일 먼저 보는 곳은 서블릿이다.
- Req,Res 객체에 대한 핸들링이 가능하다. 그래서 Request에 들어있는 인증 헤더를 볼 수 있기에 여기서도 가능한다.
- 인증,인가 되지 않은 요청을 굳이 스프링까지 가게 하지 않아도 된다.
- 세부적인 보안은 뭔가 -> 서비스 코드 단에서 추가적인 인가 과정을 거치는 경우
- HTML의 어드민 권한이 필요한데 인터셉터는 못한다. Spring context에 가지 않기에 

### 한줄 정리
- 필터: Servlet Context에 속하는 DispatcherServlet 이전에 존재하는 계층.
- 인터셉터: DispatcherServlet 이후 Controller 이전에 존재하는 계층.
- ExceptionHandler: 예외별로 개발자가 원하는 응답처리를 하기위한 Handler
- RestControllerAdvice: Spring 내에서 전역예외처리를 하기위한 관제소같은 곳.
- ResponseStatus: HTTP Code를 지정하기 위한 어노테이션
- 파일 처리: 말 그대로 파일을 처리하기 위한 방식
- 고아 이미지: 서버에 있지만 아무도 사용하지 않는 이미지.
