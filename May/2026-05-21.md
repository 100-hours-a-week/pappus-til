## 주제 1: HTTP 특징과 통신 방식

# HTTP 특징

## Stateful / Stateless

### Stateful
서버가 사용자의 상태를 기억하는 방식

강사님 비유
- 카페 알바

특징
- 서버가 이전 요청 정보를 기억
- 사용자 상태를 저장
- 요청 흐름을 이어서 처리 가능

장점
- 맞춤형 서비스 가능
- 복잡한 흐름 처리 가능
- 사용자 경험 증가

단점
- 서버 메모리 사용량 증가
- 사용자가 많아질수록 부담 증가
- 분산 시스템에서 처리 어려움

예시
- 로그인 세션
- 게임 서버
- 화상회의

---

### Stateless
서버가 사용자 상태를 저장하지 않는 방식

강사님 비유
- 키오스크

특징
- 모든 요청이 독립적
- 요청마다 필요한 정보를 다시 전달해야 함

장점
- 서버 확장에 유리
- 부하 분산 쉬움
- 대규모 트래픽 처리에 강함

단점
- 요청마다 데이터를 계속 보내야 함
- 상태 유지 어려움

예시
- HTTP
- TCP

---

## Connection Oriented / Connectionless

### Connection Oriented
연결을 먼저 맺고 통신하는 방식

예시
- 전화
- 게임
- Zoom
- 실시간 채팅

특징
1. 연결 생성
2. 데이터 송수신
3. 연결 종료

장점
- 신뢰성 높음
- 실시간 처리 가능
- 데이터 순서 보장 가능

단점
- 연결 유지 비용 존재
- 서버 자원 사용 증가

---

### Connectionless
요청 후 연결을 종료하는 방식

예시
- 문자
- HTTP

장점
- 서버 자원 효율적
- 대규모 처리 유리

단점
- 매번 연결 필요
- 상태 유지 어려움

---

## HTTP와 TCP 관계

- HTTP는 Stateless이고 Connectionless 성향을 가지지만 TCP 기반

## 인증(Authentication)

# 주제 3: 쿠키(Cookie) / 세션(Session)

## 쿠키(Cookie)

사용자의 브라우저에 저장되는 작은 데이터 파일

특징
- 클라이언트에 저장
- 문자열 형태 저장

---

## 쿠키 보안 문제

- 기본 쿠키는 사용자가 직접 확인 가능
- 평문(Plain Text) 상태라면 ,중요한 정보가 노출될 위험 존재
- 중요하거나 민감한 데이터는 다루지 않음.

---

## 세션(Session)

사용자 상태를 서버에서 저장하는 방식이다.

- 브라우저는 Session ID만 저장
- 실제 사용자 정보는 서버에서 관리

동작 과정

1. 로그인 요청
2. 서버가 세션 생성
3. Session ID 발급
4. 쿠키에 Session ID 저장
5. 이후 요청마다 Session ID 전송
6. 서버가 사용자 식별

## 장점

- 쿠키보다 보안 우수
- 중요한 정보 서버 저장 가능
- 사용자 상태 관리 쉬움

## 단점

- 서버 메모리 사용
- 사용자가 많아질수록 부담 증가
- 서버 확장 어려움

---

# 주제 6: 페이징(Paging)

방대한 데이터를 나누어서 조회하는 기술

목적
- 성능 향상
- 메모리 절약
- 사용자 경험 개선

# Offset Based Pagination

SQL 예시

```sql
SELECT *
FROM post
LIMIT 10 OFFSET 20;
```

의미
- 20개 건너뛰고
- 10개 조회

## 장점
- 구현 단순
- 이해 쉬움

## 단점

### 1. 데이터 많아질수록 느려짐

이유
- OFFSET 이전 데이터도 읽어야 하기 때문

예시
```text
OFFSET 100000
```

이면 10만 개를 건너뛰고 읽음.

### 2. 데이터 중복 가능

예시

기존 데이터
```text
1 2 3 4 5
```

새 데이터 추가 후
```text
0 1 2 3 4 5
```

다음 페이지 조회 시
- 중복 데이터 발생 가능

## 페이지 기반(Page Based)

페이지 번호 기반 조회 방식

예시
```text
?page=1
?page=2
```

사용 예시
- 게시판
- 카페
- 쇼핑몰

## 인피니티 스크롤(Infinite Scroll)

스크롤이 끝나면 다음 데이터를 자동 요청하는 방식

사용 예시
- SNS
- Shorts
- Instagram

장점
- 자연스러운 사용자 경험

단점
- 특정 위치 이동 어려움

# Page Based Pagination

단순히 Offset 기반을 사람이 이해하기 쉽게 page로 표현만 한 것인듯

예시
```text
?page=3
```

내부 계산
```text
OFFSET = (page - 1) * size
```

# Key Based Pagination

특정 키 기준으로 조회하는 방식

예시

```sql
WHERE id > 100
LIMIT 10
```

## 장점

- 빠름
- 대용량 처리에 강함
- 중복 문제 적음


## 단점

- 특정 페이지 바로 이동 어려움 
- 이전 페이지 이동 어려움

의문 : 왜 키를 사용하는데 특정 페이지 바로 이동이 어렵다고 하는거지?

---

## 왜 특정 페이지 이동이 힘들까?

Offset 방식은 "100번째부터 보여줘"가 가능하지만,
Key 방식은 "id > 100"처럼 현재 위치 기준 탐색임.

- 약간 offset은 array느낌이고 key는 list느낌으로 탐색하는 듯.

---

# Cursor Based Pagination

Key Based Pagination의 발전형

특징
- 실제 키값 대신 직렬화된 Cursor 사용

예시

기존
```text
?id=1052
```

Cursor 방식
```text
?cursor=ZDXA1231
```

의문 : 근데 직렬화만 하면 보안을 위해서 하는 것이 아니잖아? 왜 이러한 쓸데없는 일을 하는거지?

## Cursor를 사용하는 이유 (강사님의 답)

### 1. 내부 정보 숨김

키 값이 그대로 노출되면 데이터베이스의 구조나 정보를 알 수 있게 된다. 
-> 근데 이건 어차피 풀 수 있어서 상관없지 않나?
-> 다시 생각해보니 그냥 사용자가 직접적으로 알기 원하지 않는 정도지 막 완전히 숨겨야한다 정도는 아니기에 이렇게 한 듯?

### 2. URL 안정성 증가

예시 키값
```text
2026-05-21 09:40.134
```

문제점 공백, 특수문자, 소수점 등으로 URL 파싱 오류 가능
그래서 Base64 같은 방식으로 직렬화하여 사용

### 3. 복합 정렬 지원 가능

예시
```text
createdAt + id
```

같은 복합 기준 저장 가능

장점
- 중복 감소
- 안정적 페이징 가능

# Token Based Pagination

서버가 마지막 조회 위치를 저장하는 방식

특징
- 클라이언트는 토큰만 전달
- 서버가 상태를 기억

---

## Cursor Based vs Token Based

### Cursor Based
- 서버 상태 저장 X
- Stateless 성향

### Token Based
- 서버가 상태 저장
- Stateful 성향

# 오늘의 회고

오늘은 HTTP의 특징과 인증/인가,
그리고 다양한 페이징 방식에 대해 학습하였다.

특히 Stateful과 Stateless의 차이를
카페 알바와 키오스크 비유로 이해하니 훨씬 직관적으로 느껴졌다.

그리고 framework와 library의 차이에 대해서 많은 생각을 했는데 결국 엿장수 맘인것 같아서 뭔가 아쉽다.
(gpt , claude , gemini한테 물어봐도 엇갈림)

Offset 방식은 단순하지만 데이터가 많아질수록 느려지고 실시간 데이터 변화에 약하다는 점을 새롭게 알게 되었다.
Key 방식은 조금은 리소스를 차지하지만 데이터가 많아도 문제가 없다는 것을 알게 되었다.
두 가지 방식을 알게 되면서 결국 하이브리드로 좋은점을 활용하여 적절한 상황에 적절한 방식을 적용해야 겠다고 생각했다.
(알고리즘을 공부하면 할 수록 만능 알고리즘은 없다는게 체감이 확 된다.)

Cursor Based Pagination은 단순히 키값을 숨기는 목적만 있는 줄 알았는데 URL 안정성과 복합 정렬 처리 같은 장점도 있다는 점이 흥미로웠다. 정작 키값을 숨기는 목적이 상당히 느슨해서 놀랐다. 이게 주 목적인 줄 알았는데, 그냥 직렬화만 한거라니...
