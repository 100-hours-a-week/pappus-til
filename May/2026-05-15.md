#### 주제 1: 객체지향 프로그래밍(OOP)

##### 캡슐화
- 객체 내부 데이터를 외부에서 직접 접근하지 못하도록 보호하는 개념이다.
- getter/setter를 통해 데이터의 유효성 검사가 가능하다.
- 내부 구현을 숨기고 필요한 기능만 외부에 공개하여 유지보수성을 높인다.

##### 상속과 인터페이스

1. 상속 (extends)
- 상속은 `is-a` 관계를 표현하며 부모 클래스의 기능을 자식 클래스가 물려받는 구조이다.
- 자바는 클래스의 단일 상속만 지원한다.

2.인터페이스 (interface)
- 인터페이스는 `can-do` 관계를 표현하며 기능의 규약을 정의한다.
- 인터페이스는 다중 구현이 가능하여 유연한 설계가 가능하다.
- 구현 방식과 관계없이 동일한 인터페이스를 사용할 수 있기 때문에 테스트와 병렬 개발에 유리하다.

##### 제네릭(Generic)
- 필요이유 : Object 타입 사용 시 잘못된 형변환은 실행 중 오류가 발생한다.
- 제네릭은 컴파일 시점에 타입을 검사하여 타입 안정성을 높인다.
- 불필요한 형변환을 줄여 코드의 가독성과 안정성을 향상시킨다.
- `extends`를 사용하여 특정 부모 클래스로 타입을 제한할 수 있다.

#### 주제 2: 멀티스레드와 ThreadPool

##### Thread 생성 방법
- `Thread` 클래스를 상속하는 방법
- `Runnable` ,`Callable`  인터페이스를 구현하는 방법 

##### Runnable과 Callable 차이
- Runnable은 반환값이 없다.
- Callable은 작업 결과값과 예외를 반환할 수 있다.

##### new Thread 사용의 문제점
- 스레드 생성 및 소멸 비용이 크다.
- 너무 많은 스레드 생성 시 메모리 부족(OOM) 문제가 발생할 수 있다.
- 스레드를 직접 관리해야 하므로 종료 처리와 관리가 어렵다.

##### ThreadPool
- 미리 생성된 스레드를 재사용하는 방식이다.
- 스레드 생성 비용을 줄일 수 있다.
- 동시에 실행되는 스레드 수를 제한할 수 있다.
- 스레드 관리를 효율적으로 수행할 수 있다.
- `ExecutorService`를 사용하여 ThreadPool을 관리한다.

##### ThreadPool 핵심 구조
1. Runnable 또는 Callable 작업 제출
2. Blocking Queue 저장
3. Thread Pool 내부 스레드가 작업 실행

#### 주제 3: 동기화와 Lock

##### synchronized
- 여러 Thread가 공유 자원에 안전하게 접근할 수 있도록 한다.
- 한 번에 하나의 Thread만 critical section에 접근 가능하다.
- JVM과 OS 수준의 Lock을 사용한다.
- 순서상관 X

##### Critical Section
- 여러 Thread가 동시에 접근하면 문제가 발생할 수 있는 코드 영역이다.

##### Lock
- 공유 자원 접근 시 Thread가 획득해야 하는 자원이다.
- Lock을 획득한 Thread만 critical section에 접근 가능하다.

##### Starvation
- 특정 Thread가 계속 Lock을 획득하지 못하는 현상이다.
- synchronized는 공정성을 보장하지 않기 때문에 발생할 수 있다.
