## 새로 배운 내용
### 장애 전파 방지
- 장애 전파 방지는 장애를 완전히 없애는 기술이 아니라, 장애가 발생해도 전체 시스템으로 퍼지지 않도록 장애의 시간과 범위를 제한하는 설계

#### Resilience
- 회복 탄력성을 의미함.
- 시스템의 일부가 느려지거나 장애가 발생해도 정상적인 기능을 제공하고 장애를 회복하면 점진적으로 정상상태로 돌아가도록 하는 성질
- Spring에서는 resilience4j라는 라이브러리가 있음.

##### Cascading Failure
- positive feedback으로써 점점 장애가 커지는 것
- 한 기능의 장애가 점점 연쇄적으로 다른 기능까지 영향을 주는 것.

#### 해결 방식
1. 기다리는 시간 제한 (timeout)
2. 들어오는 요청량 제한 (Rate Limiter, Load Shedding)
3. 실패한 요청을 무조건적으로 반복하지 않기 (Retry)
4. 반복해서 실패하면 해당 대상은 잠시 호출하지 않기 (Circuit Breaker)
5. 자원을 나눠서 사용하기 (Bulkhead)
6. 완전한 성공이 안되면, 제한된 기능만 제공하기 (Fallback, Graceful Degradation)

#### 인프라와 백엔드의 역할 구분
| 구분 | 인프라 영역 | 백엔드 영역 |
| --- | --- | --- |
| 대표 구성 요소 | ALB, Nginx, Ingress, API Gateway, Kubernetes | Spring Boot, HTTP Client, DB Client |
| 알고 있는 정보 | IP, 연결, 요청 경로, 응답 코드, 요청량 | 사용자, 주문, 결제, 비즈니스 오류 |
| 주요 목적 | 전체 시스템으로 들어오는 트래픽 보호 | 특정 의존성과 비즈니스 기능 보호 |
| Timeout | 프록시 연결·응답 시간 제한 | 외부 API, DB, 메서드 실행 시간 제한 |
| Retry | 다른 서버 인스턴스로 제한적 재전송 | 예외와 응답의 의미를 판단해 재시도 |
| Circuit Breaker | 비정상 인스턴스를 대상에서 제외 | 특정 서비스 호출 자체를 일시 차단 |
| Bulkhead | 연결 수, Pod, 노드, 큐 격리 | 스레드 풀, Semaphore, 커넥션 풀 격리 |
| Rate Limiter | IP, 경로, API 단위 제한 | 사용자, 테넌트, 기능별 제한 |
| Fallback | 정적 오류 페이지, 캐시 응답 | 대체 데이터, 기능 축소, 명시적인 실패 |

- 인프라는 트래픽과 연결을 보호하고, 애플리케이션은 비즈니스 로직,실제 재시도를 처리함.

#### 1. Rate Limiter
- 시스템이 감당할 수 있는 범위까지만 요청을 받는 장치.
- 인프라: Nginx, Ingress와 같이 허용 범위 이상의 요청은 제한을 함.
- 백엔드: 비즈니스 기준으로 제한함.
  - 예: 사용자당 이메일 인증을 1분에 5회로 제한함.
  - 이와 같이 서비스의 안정성을 위해서가 아니라 비즈니스 로직에 의해 제한함.

#### 2. Timeout
- 응답하지 않는 작업을 무한히 기다리지 않도록 기다리는 시간에 상한을 두는 장치.
- 인프라: Nginx에서 일관적으로 timeout을 설정할 수 있음. 
- 백엔드: 비즈니스 로직에 따라서 일관적인 타임아웃이 아니라 다르게 적용할 수 있음. 
- 너무 짧은 타임아웃은 정상적인 요청을 타임아웃 시킬 수 있어서 적절하게 잡는 것이 중요함.
  - p95,p99값을 측정하고 이를 기준으로 설정하는 것이 좋음.

#### 3. Retry
- 일시적인 실패일 가능성이 있을 때 요청을 제한된 횟수만큼 다시 시도하는 방식
- 분산 시스템과 같이 일시적으로 실패 가능성이 항상 존재하는 것에 대해서 재시도를 요청함.
  - 잘못된 요청(인증 실패, 권한 부족 등)은 재시도를 하면 안됨.

#### 4. Bulkhead
- 하나의 기능이나 의존성이 전체 자원을 사용하지 못하도록 자원을 분리하는 방법
- 제공하는 서비스 별로 스레드 풀을 분리해서 하나의 서비스 요청이 전체 스레드 풀을 사용하는 것을 예방.
- 하지만 각 기능별로 분리하는 것이기에 유동성이 떨어져서 자원을 최대한 활용하지는 못함.
- 백엔드: Semaphore Bulkhead, Thread Pool Bulkhead
- 인프라: Nginx, K8s
  
#### 5. Circuit Breaker
- 계속 실패하는 서비스에 요청을 보내지 않고 빠르게 실패시키는 장치
- 전기설비의 퓨즈같은 것, 외부 서비스가 계속 실패하거나, 느리게 호출될 때 호추를 차단하는 역할.
- Closed, Open, Half-Open의 상태를 가질 수 있음.

#### 6. Fallback
- 정상적인 결과를 제공할 수 없을 때, 전체 실패 대신 제한된 결과를 제공하는 방법임.
